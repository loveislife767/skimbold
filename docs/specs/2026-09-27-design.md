# Skimbold — design spec (v1.0, 2026-09-27)

## 1. Intent

- **What Simon asked for:** a browser extension that bolds the first 1, 2 or 3 letters of each word so text is quicker to read. It should come up on demand while reading on the computer. It must be free, published so other people can use it, and posted to GitHub. A phone app comes *later* and is not part of this spec.
- **Decided without asking**, per Simon's standing "just do it" preference:
  - **Browsers.** Simon's default browser is Brave (Chromium), and Chrome is installed too. The primary target is Chromium Manifest V3 (Chrome, Brave, Edge, Opera). A Firefox build is produced from the same source.
  - **Reader page.** "Reading something on my computer" is mostly web pages, but also PDFs and pasted text. So we ship a Reader page that takes pasted text or opens .txt, .md, .html and .pdf files.
  - **Licence and privacy.** Free forever, MIT licensed, no tracking, and no network requests of our own.
  - **Naming.** The name of the commercial reading method this resembles is a registered trademark. It never appears in the name, the listing, the manifest, shortcut descriptions, code identifiers or these docs. Describe the technique generically ("bolds the start of every word").
  - **Claims.** No speed claims. Studies found no measurable reading-speed gain (Snell 2024; Readwise n=2,074; Beelders 2025), and store policy treats misleading claims as grounds for rejection. The wording is "helps you focus and keep your place".
- **Success criteria**
  1. On a normal web page, one shortcut or one click bolds word starts. A long article finishes within ~300 ms of main-thread work, in slices. Pressing it again restores the page *exactly*: a static page's `body.innerHTML` is byte-identical to the original.
  2. Never breaks sites:
     - inputs, editors, code and math are left alone;
     - React, Vue and Svelte apps keep working, with no `removeChild` crashes, no stale or duplicated text, and no invisible text;
     - styles still apply under strict CSP and Trusted Types.
  3. Settings apply live: bold letters (Auto, 1, 2 or 3), strength, fade and weight.
  4. The Reader opens pasted text and text-based PDFs.
  5. Public GitHub repo with:
     - a README;
     - CI;
     - release zips;
     - a GitHub Pages site (landing page with live demo, privacy policy, web version of the Reader);
     - a store kit ready to upload (listing text, screenshots, promo tiles, permission justifications).

## 2. Architecture

- **No bundler.** Every source file is a plain classic script, except `reader/pdf-worker.mjs`, the module that starts the pdf.js worker.
- **One shared namespace object, `globalThis.Skimbold`.** Because of this, the same files load unchanged in:
  - content scripts;
  - the Chrome service worker (via `importScripts`);
  - the Firefox event page (listed in `background.scripts`);
  - extension pages (via `<script src>`);
  - the web build;
  - Node tests (UMD tail: `if (typeof module === 'object' && module.exports) module.exports = …`).

## 3. `shared/core.js`: the algorithm (pure)

```js
Skimbold.core.boldLength(letterCount, opts) → integer ≥ 0     // letters (graphemes) of a word to bold
Skimbold.core.transform(text, opts, state?) → Part[] | null   // null when nothing in `text` gets bolded
   Part = { t: string, b: boolean }                            // concatenated t === text, adjacent parts differ in b
Skimbold.core.WORD_RE, Skimbold.core.isEligibleWord(word)     // exported for tests
```

**Options and state**
- `opts`: `{ mode:'auto'|'fixed', strength:1..5, letters:1..4, skipShort:0..3, everyNth:1..3 }`, a subset of the settings.
- `state` (optional, mutable): `{ count }`. It keeps a running count of eligible words so `everyNth` stays regular across the many text nodes of a page. The engine passes one state object per scan pass.

**What counts as a word**
- A word is a maximal run of letters, marks and digits, with internal apostrophes (`'` `’`) that are followed by more letters: `/[\p{L}\p{M}\p{N}]+(?:['’][\p{L}\p{M}\p{N}]+)*/gu`.
- Hyphens, slashes, dots and underscores split words: `well-known` becomes `well` + `known`.

**Which words are eligible**
- A word is eligible only if its first code point is a letter in one of these scripts: **Latin, Greek, Cyrillic, Armenian, Georgian or Hebrew**.
- Everything else is left untouched: numbers and number-led tokens like `2nd`, CJK, Thai/Lao/Khmer/Myanmar, Arabic and other joined scripts, Indic scripts, emoji.
- Reason: splitting a shaped or cursive script, or a script written without spaces, breaks the rendering.

**Counting letters**
- Letter count = number of grapheme bases, i.e. code points that are not `\p{M}` and not apostrophes.
- The bold prefix never separates a base letter from its combining marks. `café` stays intact.
- The bold prefix never ends on an apostrophe: `don't` with n=3 becomes **don** + `'t`.

**How many letters to bold** (`L` = letter count)
- `L ≤ skipShort` → 0, so the word stays plain. Default `skipShort` is 0.
- `mode:'fixed'` → `n = letters`.
- `mode:'auto'` → `n = round(L × ratio)`, where `ratio = [0.25, 0.33, 0.4, 0.5, 0.6][strength-1]`. Default strength is 3, i.e. 0.4.
- Clamp afterwards: `n = max(1, min(n, L === 1 ? 1 : L - 1))`. A word of two or more letters always keeps a non-bold tail; fully bold short words are just visual noise.
- The result must be **monotonic non-decreasing in L** for every setting. Unit-test this; the text-vide FP4 table breaks this rule.
- Default table (auto, strength 3): 1→1, 2→1, 3→1, 4→2, 5→2, 6→2, 7→3, 8→3, 9→4, 10→4, 12→5.

**everyNth**
- With N > 1, only every Nth eligible word is bolded.
- The first eligible word is #1 and is bolded.

## 4. `shared/settings.js`

```js
Skimbold.settings = { DEFAULTS, sanitize(obj), async load(), async save(partial), onChange(cb) → unsubscribe, originOf(url) }
DEFAULTS = {
  mode:'auto', strength:3, letters:2, skipShort:0, everyNth:1,
  weight:700,            // 600|700|800|900 — font-weight of the bold part
  fade:0,                // 0..60 — % the rest of each word is faded (0 = off)
  iconClick:'popup',     // 'popup' | 'toggle'
  autoSites:[],          // origins ("https://example.com") where Skimbold turns on by itself
  autoAll:false,         // turn on by itself everywhere…
  excludedSites:[],      // …except these origins (only meaningful with autoAll)
  reader:{ theme:'auto', fontSize:20, lineHeight:1.7, font:'serif', width:680, bold:true }
}
```

- **Where settings live:**
  - In the extension: one key, `settings`, in `chrome.storage.sync`.
  - On the web: `localStorage['skimbold.settings']`, used when `chrome.storage` is absent.
  - In Firefox, use `browser ?? chrome`.
- **`sanitize`:**
  - clamps every field;
  - normalises origin lists (valid http/https origins only, deduped, max 500);
  - drops unknown keys.
- **`load` never throws.** On any error it returns `DEFAULTS`.
- **`onChange`** fires with the full sanitized settings. It uses `storage.onChanged` in the extension and the `storage` event on the web.

## 5. `content/engine.js`: DOM engine

**API and messages**
- API: `Skimbold.engine = { enable(), disable(), toggle() → bool, isActive() → bool, refresh(), choices() → count }`. `choices()` counts explicit on/off requests (`skb:toggle`, `skb:set` without `sync`), so auto.js never overrides the user.
- Idempotent under re-injection: bail out if it's already defined.
- Registers exactly one `runtime.onMessage` listener:
  - `{type:'skb:toggle'}` → `{active}`
  - `{type:'skb:set', active, sync?}` → `{active}`; `sync: true` marks a frame being brought in line with the top frame, not a user choice
  - `{type:'skb:getState'}` → `{active, pdf}`, where `pdf` is `document.contentType === 'application/pdf'`
- Subscribes to settings changes and calls `refresh()` while active.
- Only the top frame reports `{type:'skb:state', active}` to the background, on every change.
- Any frame that is on sends `{type:'skb:frames', frameIds, fresh}` when iframes in it load (coalesced over 150 ms), so the background brings those frames to the top frame's state (§7):
  - `frameIds` names the frames that loaded when that is known: from `runtime.getFrameId(iframe)` (Firefox), or in Chromium from the id a same-origin frame noted on its own element (a `skimboldFrameId` property in the isolated world, which same-origin frames share) when a sync message told it (`skb:set` carries `frameId`);
  - `fresh` says that an iframe element it had not seen before loaded (the iframes present when the page was turned on count as seen, unless `enable()` waited for the page to load);
  - a subframe that is on sends `{type:'skb:frames', leaving:true}` on `pagehide`, so the background knows which frame is loading a new page.
- `enable()` on a page that is still loading waits for `load` (at most until 3 s after the page opened, counted from its navigation, so a page whose ads hold `load` back is not kept waiting once it is readable) and a moment of idle before it scans, so server-rendered apps hydrate first; it reports `active` straight away. It does nothing in a frame's placeholder `about:blank`, that is while its `frameElement` has a `src` (other than `about:blank`) or a `srcdoc` on its way (Chromium keeps the content-script world when the frame's first page replaces it). An `about:blank` frame with nothing on its way is the page's own, filled by script, and is bolded like any page.

**Markup**
- A `<skb-w>` wrapper holds the text of one original text node. Inside it are text nodes plus a `<skb-b>` for each bold prefix.
- The wrapper carries `data-skb-weight="600|700|800|900"` when its text is already that heavy, and `data-skb-fill` when the text paints with its own `-webkit-text-fill-color` (gradient text); the stylesheet uses them (below).
- Never build it from HTML strings: no `innerHTML`/`insertAdjacentHTML` with page text. That caused XSS and `&amp;` bugs in prior extensions, and YouTube enforces Trusted Types.
- Use `createElement`, `createTextNode` and `textContent` only.

**Styles**
- Pages reset `b`/`strong`, style unknown elements, or hide undefined custom elements (e.g. `:not(:defined){visibility:hidden}`, the likely cause of Reddit's invisible text). The rules below win because they are `!important` and carry ID-level specificity:
```css
:is(skb-w, skb-b):not(#skb-_) { all: unset !important; display: inline !important; visibility: inherit !important; }
/* synthesis: a page with font-synthesis: none and no bold face would hide the bold */
skb-b:not(#skb-_) { font-weight: <weight> !important; font-synthesis-weight: auto !important; }
/* text at least as heavy as <weight> keeps its own weight: never lighter, and never a heavier
   face, which can be another font with taller lines (Arial Black on Windows) */
:is(skb-w[data-skb-weight="<w ≥ weight>"], …):not(#skb-_) > skb-b:not(#skb-_) { font-weight: inherit !important; }
/* only when fade > 0 (tail colour is derived from the text's own colour, never a fixed colour);
   gradient text (data-skb-fill) keeps its own fill: */
skb-w:not([data-skb-fill]):not(#skb-_) { -webkit-text-fill-color: color-mix(in srgb, currentColor <100-fade>%, transparent) !important; }
skb-w:not([data-skb-fill]):not(#skb-_) > skb-b:not(#skb-_) { -webkit-text-fill-color: currentColor !important; }
```
- **Getting the stylesheet in:** it must apply on pages with strict CSP (`style-src 'self'`) and `require-trusted-types-for 'script'`.
  - Prefer a constructed `CSSStyleSheet` pushed onto `document.adoptedStyleSheets` and each processed shadow root's `adoptedStyleSheets`; CSSOM is not subject to CSP.
  - Fall back to a `<style id="skb-style">` element if adopting throws. Firefox's Xray wrappers may make it throw.
  - Remove the stylesheet on disable.
  - The e2e tests cover the strict-CSP case.

**Sentinel technique (SPA safety).** For an eligible text node `T` holding text `s`:
1. Build wrapper `W` from `core.transform(s)` and insert it immediately **after** `T`.
2. Set `T.data = ''`. `T` stays in the DOM, so a framework holding a reference to it can still `removeChild(T)`, `insertBefore(x, T)` or set `T.nodeValue`.
3. Track in WeakMaps: `wrapperOf` (T→W), `sourceOf` (W→T), `textOf` (T→string).

**Isolated world only.** The engine runs only in the content script's isolated world and changes nothing in the page's JavaScript world: it patches no prototype and puts no script into the page. So page scripts see the real DOM: an emptied source reads `''`, and the words are in the wrapper's own text nodes.

**Page-owned wrappers.** When the page edits inside a current wrapper (a record whose target is inside `W`: a `childList` change, or a `characterData` change to a different value), `W` becomes page content, such as a search highlighter's `<mark>`:
- it is never re-rendered (settings changes);
- when the page writes new text to its source, the page's text wins: `W` is removed and the source is wrapped afresh;
- when the batch that edited inside `W` also moved or removed its source (a range's `extractContents()` or `deleteContents()` from inside `W` into the next element takes the emptied source along), `W` is taken apart where it stands, as below, and the source is no longer tracked: what the range left of `W` stays in place, as it would in the page's own text node;
- on disable, and wherever it is handed back (zones, editing, detached subtrees), it is taken apart in place: each `skb-b` is replaced by its children, the text the bold parts split is merged again (`normalize()` on `W`, so the page gets whole text nodes back and a later turn-on bolds whole words), `W` is replaced by its children, and the text up to the first element goes back into the source, where it would have stayed had the page split that node itself. The source stays in the page even when it is left empty, because a framework may still hold it (React's `removeChild`). No `skb-*` markup and no text is lost, and the page's marks stay.

**MutationObserver.** There is one per root: the document plus every processed open shadow root. Options: `{childList, subtree, characterData, characterDataOldValue}`.
- **The page changes a tracked `T`'s text.** A record for `T` with `oldValue === ''` must be the page, because our own clears always have a non-empty `oldValue`.
  - If `T.data !== ''`: set `textOf` to `T.data`, re-render `W`, then set `T.data = ''`.
  - If the page explicitly set `''`: remove `W` and stop tracking `T`, so the element is really empty (`:empty`); a later write is wrapped afresh.
  - Except for a text walker: a script that walks text nodes in tree order and writes each one (back, or changed: a transliteration) writes the emptied source just before the text nodes inside its wrapper. A write to a source whose next record in the batch is a `characterData` write inside that source's own wrapper is the walker's, since a framework never writes inside a wrapper. An empty source keeps its wrapper, which holds whatever the walker made of the text. A source the walker wrote text into (it appended to every node) is handed back in place with its wrapper taken apart, and the scan wraps the result. This is done within the reconcile budget, the rest in the next slices, and a wrapper that holds only its bold parts and text is merged in one step (piece by piece, a walker over a 2,000-paragraph page blocked it for 1.6 s). Any other write to the same source in the batch (the page clearing it before or after the walk) decides as usual. A walker that writes one node per task, or replaces each node with a new one, is not recognised.
- **The page removes `T`:** remove `W`.
  - Except where the page took an element apart: a record that replaces an element the page emptied earlier in the batch with nodes (its own children) is a search highlighter clearing its marks, which then `normalize()`s the parent and so removes the emptied sources there. mark.js puts all of a mark's children in its place, jQuery's highlight plugin only the first (`T`, so `W` went with the mark). A `T` removed after that by a record that adds nothing (`normalize()` only removes), in one of those parents or marks or inside them, gets a new empty source where `W` is, or, when `W` left the page, `W` and a new source go where `T` was, right after the node before it (which `normalize()` keeps: it works in tree order). Where the removal happened is decided once the whole batch is known: `normalize()` of the first mark's parent already reaches into the next mark, which the page takes apart only later. Anywhere else in the batch (the page clearing its results line in the same handler), and in any batch where nothing was taken apart (React, Vue and the like never take an element apart), `removeChild(T)` still removes `W`.
- **The page removes a subtree holding wrappers:** whatever is still off the page when its records are handled gets its text back, so edits the page makes while it is detached (recycled rows) show when it returns. Done within the reconcile budget, the rest in the next slice.
- **The page removes `W` and writes `T`:** `T` keeps the page's text and is wrapped afresh.
- **The page moves `T`:** move `W` to follow it.
- **The page inserts a node directly after `T`:** move `W` back after `T`. Vue computes insertion anchors with `nextSibling`.
- **The page removes `W` but `T` survives:** restore `T.data = textOf(T)` and stop tracking `T`.
- **YouTube appends after `W`:** YouTube's DOM layer reads an element's children through a scoped view that skips comments, blank text nodes and elements of other scopes (ours), so a `yt-formatted-string` holding only blank text, `T` and `W` looks empty to it. Its `updateText_` then appends the new text instead of replacing `T` ("Comments2,457,730 Comments", also after off). A record that only adds nodes right after such a `W` in a `yt-formatted-string` counts as the page clearing `T`: `W` goes and `T` stays empty, which YouTube's view skips on its next update too. The engine cannot tell this from an ordinary append in general, so the rule is limited to that element.
- **Added nodes:** queue them for scanning. Ignore nodes that are, or are inside, our wrappers.
- **Late shadow roots:** a record whose target (or, for text, whose parent) is an element with an open shadow root we have not attached makes the engine attach it. A custom element defined later attaches its root as it upgrades, which no record shows, so the custom elements (a `-` in the tag name) the scan found without a shadow root, the root of an added subtree included, are looked at again in idle time, time-sliced, every 2 s; after five looks in a row that find nothing with no records in between, the looks stop until the page changes again.
- **Streaming:** a container whose wrapped (or held-back) text the page replaces again within 250 ms is re-rendering (a chat answer rebuilt as HTML per token, a ticker). Replacing means a record that removes and adds in one go, or one that removes from the middle; a record that only removes at one end (blank text and comments aside) is a list keeping its last N entries (a live chat), and what it appends is wrapped at once. New content in a re-rendering container waits until the container has been quiet for 200 ms, but never more than 400 ms. Copies of our markup in content that waits are settled (adopted) at once all the same. Nodes the page removes and puts back in the same batch are moved (a keyed list reordered), not replaced. A container that throws away wrappers made less than 100 ms before, five times, fights the engine: its new text waits until the container has been quiet for 1 s, and then gets one more try; each try it throws away again doubles the next wait, up to 16 s. Text the page rewrites in place (`characterData`) in a container that re-rendered waits the same way: React sets the text of an element whose only child is text in place, and replaces the children whole once `W` sits beside it.
- **Self-mutation hygiene:**
  - Before our own DOM writes, `takeRecords()` and handle those records.
  - After our writes, `takeRecords()` and discard them.
  - The observer must never react to its own changes (Jiffy's GitHub freeze was exactly this loop).
- **Streaming-heavy pages** (chat, live feeds): coalesce re-scans. Work is batched per animation frame or idle slice, never one scan per mutation.

**Scanning**
- A queue of roots is processed with a `TreeWalker(SHOW_ELEMENT|SHOW_TEXT)` in time slices of ≤ 8 ms each.
  - Yield via `scheduler.yield()` when available, otherwise `setTimeout(0)`.
  - The first slice runs synchronously on enable and is kept to about 1 ms (its rendering lands in one frame); mutation-driven work starts the same way.
  - Content in or near the viewport should go first if that's cheap (e.g. start with the walker at `document.body`, but queue off-screen large subtrees later); document order is acceptable.
- Text nodes are wrapped in batches: every read first (what to bold, and the computed style of each parent, cached for 1 s), then every write, so a batch costs at most one style recalculation. A batch is flushed before its estimated cost would pass the slice's deadline, or at 512 text nodes (the estimate goes by characters, and lags behind on runs of tiny nodes such as table cells).
- From the parent's computed style: a text node with another text node beside it (comments and empty text between do not count) in a flex or grid container is left plain (one anonymous item; wrappers would split it); a single lower-case token in an icon font (first family matches `icons|symbols`) is left plain (ligature); weight and own-fill markers are set on the wrapper; with `text-transform: capitalize` the emptied source is re-inserted (Chromium keeps stale capitalization state otherwise).
- **The element filter rejects (skips the whole subtree of):**
  - `SCRIPT STYLE NOSCRIPT TEMPLATE TEXTAREA INPUT SELECT OPTION BUTTON CODE PRE KBD SAMP VAR TT SVG MATH CANVAS VIDEO AUDIO IFRAME OBJECT EMBED HEAD TITLE`;
  - any `skb-w`;
  - `[contenteditable]` other than `"false"`, and `[role="textbox"]`;
  - `[data-skimbold-skip]`;
  - editor, terminal and math containers: `.monaco-editor .CodeMirror .cm-editor .ace_editor .xterm mjx-container .MathJax .katex .MathJax_Display`, plus MathJax 2's fast preview and its other outputs: `.MathJax_Preview .MathJax_CHTML .MathJax_PHTML .MathJax_SVG`;
  - captions a video player sizes to their measured text (bolded, they wrap onto extra lines): `.ytp-caption-window-container` (YouTube), `.vjs-text-track-display` (video.js), `.jw-captions .jw-text-track-container` (JW Player), `.plyr__captions` (Plyr), `.shaka-text-container` (Shaka), `.bmpui-ui-subtitle-overlay` (Bitmovin);
  - icon fonts: `mat-icon md-icon mwc-icon`, `[class*="material-icons"] [class*="material-symbols"] [class*="google-symbols"] .mat-icon`;
  - `astro-island[ssr]` (an island that has not hydrated; `ssr` is watched and the island is scanned once Astro removes it);
  - an `[aria-hidden="true"]` copy of a field's text: its box touches an `input` or `textarea` with fully transparent text (`color` or `-webkit-text-fill-color`) inside one of its three nearest ancestors. Pages that style what is typed (GitHub's search and filter bars, its code view) draw the field's text in such a copy; bolded, it would be wider than the field's own text, and the caret and selection would drift from it;
  - light-DOM content assigned to a slot that sits in one of these zones (a web component's `<pre>`). When a shadow root is attached later (see late shadow roots), light-DOM children it slots into a zone that are already wrapped are handed back.
- An element moved into a zone (a bolded paragraph moved into an editor) gets its text back.
- **Also:**
  - Skip text nodes that look like unrendered TeX (`\(` `\[` `$$` or `$…$` with a backslash inside), because MathJax may still be about to process them.
  - If `document.designMode === 'on'`, do nothing.
  - Skip whitespace-only text nodes cheaply.
  - Process open shadow roots (`el.shadowRoot`): adopt the stylesheet, attach an observer, scan the contents.

**Disable**
- Stop the observers and any pending work.
- For every wrapper in every root: if `T` is still empty, give it the text its wrapper shows (normally `textOf(T)`; text typed into a wrapper wins); then remove `W`. A page-owned wrapper is taken apart in place instead (above).
- Then every `skb-w`/`skb-b` still in a root (`querySelectorAll`) becomes plain text, or its children when it holds page markup: copies the engine never adopted, such as content that was waiting for its container to go quiet.
- Remove the stylesheets.
- Result on a static page: identical `innerHTML`.
- Afterwards, a light `childList` observer on the document and former shadow roots turns copies of our markup that the page puts back (cached `innerHTML`) into plain text, until the next enable.
- Restoring is sliced like scanning, last source first. Turned back on before it has finished, the engine keeps what is still wrapped: those sources are tracked again (the ones the page changed meanwhile are reconciled), the roots are observed again with their stylesheets, and the scan wraps the rest. Restoring everything first blocked the page for 0.1–0.4 s on a 250,000-word page.

**Around the page**
- **Copy and drag:** when a `copy` or a selection `dragstart` takes wrapped text and the page has not handled it, `text/html` is rebuilt from a clone of the selection with `skb-w`/`skb-b` replaced by their contents (inline ancestors such as a link kept, links made absolute) and `text/plain` is the selection's text. A real selection drag in Chromium can start on the element under the pointer rather than on a text node, so a `dragstart` is a selection drag when the selection is not collapsed and intersects the node the drag started on, unless the browser put `text/uri-list` in it: a link or an image dragged on its own, even one pressed where the selection ends inside it. Pressed on a link inside the selection, Chromium drags the selection (no `text/uri-list`), which is rebuilt too. Its `text/plain` is no guide: Chromium writes it with CRLF line breaks and image alt text, so it differs from `Selection.toString()`.
- **Editing:** a `beforeinput` with `document.designMode === 'on'` disables synchronously before the edit lands; one in an editing host that holds wrappers hands those back.
- **Selection:** a selection end in text that is wrapped, re-rendered or handed back is put back on the same character.

**Refresh** (settings changed)
- Regenerate the stylesheet text. The sheet is replaced only when its text changed: new rules make the browser restyle every element, even when they are the same.
- Re-render every wrapper from `textOf`, with a fresh `everyNth` state.

## 6. `content/auto.js`

- It is injected by the registered auto-on content script after settings/core/engine.
- It must not interfere with SSR hydration (React/Next hydrate after `document_idle`):
  - wait until `document.readyState === 'complete'`;
  - then wait for `requestIdleCallback` (timeout 1500 ms);
  - then check settings (the origin is still auto and not excluded);
  - then `Skimbold.engine.enable()`, unless `engine.choices()` changed during the wait: the user's on/off choice stands.

## 7. `background.js`

**Setup**
- Chrome: `if (typeof importScripts === 'function') importScripts('shared/settings.js')`.
- The Firefox manifest lists `shared/settings.js` before `background.js`.
- Use `api = globalThis.browser ?? globalThis.chrome`, promise style.
- Guard every optional API; `commands` and `contextMenus` don't exist on Firefox Android.
- It must run as a service worker (no DOM, no `window`) and as a Firefox event page.
- Register all listeners synchronously at the top level.

**`toggleTab(tab)`**
- If the URL is restricted, return `{ok:false, reason:'restricted'}`. Restricted means:
  - `chrome:`, `edge:`, `brave:`, `opera:`, `vivaldi:`, `about:`, `view-source:`, `chrome-extension:`, `moz-extension:`, `devtools:`;
  - `https://chromewebstore.google.com`, `https://chrome.google.com/webstore`, `https://microsoftedge.microsoft.com/addons`, `https://addons.mozilla.org`;
  - on Firefox only, the hosts of its default `extensions.webextensions.restrictedDomains`: `accounts-static.cdn.mozilla.net`, `accounts.firefox.com`, `addons.cdn.mozilla.net`, `addons.mozilla.org`, `api.accounts.firefox.com`, `content.cdn.mozilla.net`, `discovery.addons.mozilla.org`, `install.mozilla.org`, `oauth.accounts.firefox.com`, `profile.accounts.firefox.com`, `support.mozilla.org`, `sync.services.mozilla.com`.
- Otherwise:
  1. Ask the top frame for its state: `tabs.sendMessage(tabId,{type:'skb:getState'},{frameId:0})`.
  2. If nothing answers, inject `['shared/settings.js','shared/core.js','content/engine.js']` into the top frame only and wait for that.
  3. Send `{type:'skb:set', active:!wasActive}` to frame 0; its reply is the page's state (a subframe such as an embedded PDF or a design-mode editor may decline). Then send the same to all frames without waiting.
  4. When the page is now on, `syncFrames`: one `executeScript` of a tiny function into all frames (`injectImmediately:true`: a lazy or still-loading frame must not hold anything up) reports the engine's state in each; frames without the engine get the engine files, and those and the frames where it is off get `{type:'skb:set', active:true, sync:true, frameId}`, one message per frame. Frames already on are left alone. Frames that load later ask for this again with `skb:frames`.
- If injection fails, return `{ok:false, reason:'blocked'}`, e.g. for `file://` without file access, or `reason:'pdf'` when the URL path ends in `.pdf` (Firefox's PDF viewer refuses scripts). A refusal alone never makes a page a PDF: Firefox refuses other pages too. A PDF whose address has no `.pdf` (arXiv) is recognised where the engine can be injected, from its `getState` report (`document.contentType`).
- Returns `{ok, active}`.

**Badge**
- Tab-scoped `ON` text, set from `skb:state` messages, with the accent colour as background.

**Command**
- `toggle-page`: suggested `Alt+R`, Mac `MacCtrl+Shift+R`, description "Toggle Skimbold on the current page" → `toggleTab` on the active tab.
- On install, if `commands.getAll()` shows an empty shortcut (a conflict), store a flag so the popup can tell the user.

**Context menus** (recreated on `onInstalled`)
- page: "Toggle Skimbold on this page";
- selection: "Open selection in Skimbold Reader". The text goes into `storage.session` under a random key, then `reader/reader.html?session=<key>` opens;
- action: "Open Skimbold Reader".

**Icon click**
- `iconClick === 'toggle'`: `action.setPopup({popup:''})`, and `action.onClicked` → `toggleTab`.
- `'popup'`: restore the popup.
- Applied at startup and whenever the settings change.

**Auto-on**
- One registered content script, id `skb-auto`, `js`: `shared/settings.js, shared/core.js, content/engine.js, content/auto.js`, `runAt: 'document_idle'`, `allFrames: true`, `persistAcrossSessions: true`:
  - `matches` = everywhere ? `['*://*/*']` : `autoSites.map(o => o + '/*')`, filtered to origins we currently hold permission for. Everywhere means `autoAll` *and* this browser holds `*://*/*` (settings sync between browsers, permissions do not);
  - `excludeMatches` = `excludedSites` patterns, only when everywhere. A port is kept (`http://localhost:3000/*`) on Chromium; on Firefox, which rejects ports in patterns, such origins are left to auto.js.
- Reconciled on install, on startup, on settings change, and on `permissions.onAdded` / `onRemoved`. A removed permission drops its origin from the settings.

**Messages from extension pages**
- `{type:'skb:toggleTab', tabId}` → `{ok, active, reason}`
- `{type:'skb:getTabInfo', tabId}` → `{restricted, active, pdf, origin, url, incognito}`; `pdf` when the URL path ends in `.pdf` or the engine reports it; a tab whose address the browser hides is asked for its `document.contentType` directly
- `{type:'skb:reconcile'}` → re-register the auto-on script.

**Messages from content scripts**
- `{type:'skb:state', active}` from frame 0 → badge.
- `{type:'skb:frames', frameIds, fresh}` → `syncFrames` for that tab; it only re-applies the page's own state. Coalesced per tab: at most one sync every 500 ms, with the frame ids of all requests since, and each frame at most once every 2 s (a frame that keeps reloading, like an ad slot, waits for its turn). The ids are those the page named plus the frames that announced `{type:'skb:frames', leaving:true}` since; each is asked `skb:getState` first, and only a frame that does not answer gets the engine. With no id known, a `fresh` frame, or more than 64 ids, every frame is looked at as in step 4; a look at every frame that finds nothing to do doubles the wait before the next one (up to 8 s) until a request names a frame or a fresh one. A named frame that cannot be reached (its element was moved, which makes a new frame) leads to a look at every frame.

**Private windows:** the Reader is an extension page, which opens in a regular window. A selection or PDF sent from an incognito tab opens it with `&private=1` (also from the popup), and the Reader then keeps nothing of it (§10).

**Permissions**
- `activeTab`, `scripting`, `storage`, `contextMenus`.
- `optional_host_permissions: ["*://*/*"]`, requested per origin only when the user switches on "Always on for this site" (or everywhere).
- No static host permissions, so there is no scary install warning and review is quicker.

## 10. Reader (`reader/`)

**Where it runs**
- As an extension page and as a plain web page (the web build on GitHub Pages).
- The future phone app starts from this page.

**Toolbar**
- Open file: .txt .md .html .htm .pdf
- Paste
- Bold on/off
- Letters and strength (shared settings)
- Theme: auto, light, sepia, dark
- Font: serif or sans
- Size − / +
- Width

**Empty state:** a large paste/drop zone.

**Rendering**
- Text is split into paragraphs at blank lines.
- HTML files are parsed with `DOMParser` into headings, paragraphs and list items. Untrusted markup is never passed to `innerHTML`.
- Bolding uses `core.transform`, output as `<span class="skb-rb">`.

**Memory**
- Remembers the last document and scroll position in `localStorage`, wrapped in try/catch. This is a per-viewer convenience.
- Documents over 4 MB are not remembered.

**Inputs**
- `?session=<key>`: a selection handed over by the background. Read it, then delete it.
- `?pdf=<url>&tab=<id>`: a PDF opened from a tab. Try these in order:
  1. `scripting.executeScript` in that tab, fetching the URL same-origin (keeps cookies, works for logged-in course sites) and returning base64;
  2. a direct `fetch(url)`;
  3. an explanation plus a file picker.
- On the website, `?pdf=` is only followed for a same-origin URL; any other shows a notice and the file picker (nobody can link people to the official Reader showing their PDF).
- `&private=1`: the document came from a private window; it is shown but not remembered, its position is not saved, and a reload does not bring it back.
- A file's content decides over its name: a PDF signature makes it a PDF, binary data (NUL bytes, no UTF-16 BOM) is refused, whatever the extension.
- Parsing is sliced like rendering (plain text, Markdown line by line, HTML by top-level part). Any unexpected error ends the busy state with a message.

**PDF → text**
- Uses the vendored pdf.js, loaded lazily with dynamic `import()` and `isEvalSupported:false`, after `reader/pdf-support.js` (fallbacks, added only where missing, for newer JavaScript the modern build calls unguarded: `Promise.try`, `Uint8Array` hex/base64, `Map`/`WeakMap` `getOrInsert(Computed)`, `Math.sumPrecise`, `URL.parse`, `Response#bytes`, `ReadableStream` async iteration). The worker entry is `reader/pdf-worker.mjs`, which imports the same file and then the unmodified worker. pdf.js still needs the `Iterator` global (Chromium 122); without it the Reader says the browser is too old, as it does for any "… is not a function" failure.
- Text items are grouped into lines by y position, and lines into paragraphs by vertical gaps.
- Hyphenation at line ends is joined; spaces are inserted where items don't touch.
- Page separators are kept.
- Friendly messages for image-only ("no selectable text — scanned?") and password-protected PDFs.

## Known limitations (documented in README)

- **Wrapper elements count for structural selectors.** CSS like `a:last-child` or `label + input` can stop matching when a wrapper lands between elements. Every approach that wraps page text has this.
- **Bold text is wider**, so text reflows. The browser's scroll anchoring keeps your reading position. A one-line label cut with `text-overflow: ellipsis` loses a few more characters.
- **Heavy and Black on Windows:** Arial has no 800 face, so bold starts at 800 or 900 in lighter Arial text are drawn in Arial Black, whose taller line box makes those lines a little taller (text already that heavy keeps its own weight, §5).
- **Some screen readers may announce a split word in pieces.** Skimbold is a visual aid, so turn it off when you use a screen reader.
- **Page scripts that work on single text nodes.** Skimbold changes nothing in the page's JavaScript world, so a script sees each emptied source as `''`:
  - `normalize()` on an ancestor of sources removes them, and their words disappear until the page draws them again (the engine cannot tell this from a framework removing a text node, where the wrapper must go), except where the page just took an element apart (a highlighter clearing its marks, §5);
  - a text walker that writes one node per task writes `''` into each source on its own, which looks like the page clearing that text; so does one that is not in tree order (backwards, or element by element: `querySelectorAll('p')` and then each one's `childNodes`, which never enter a wrapper) or writes other nodes between a source and the text in its wrapper: the words go, also after off. One that replaces each node with a new one removes the sources, which looks like the page removing them;
  - in-place appends to a held source (`data +=`, `appendData`, a typewriter effect) replace the held text with the appended part, also after off; `splitText` on it throws `IndexSizeError`;
  - scripts that search one text node at a time (find-and-replace, mark.js by default, jQuery highlight) don't find a word whose start is bold; `Range.surroundContents` fails on a range that starts or ends inside a bold start; highlighters that search across elements (mark.js `acrossElements`) work, and their marks stay after off; the page's own later write to a source whose wrapper a highlighter edited replaces the whole wrapper, its marks and the text after them included (the page's text wins, §5);
  - scripts that step through child nodes (`firstChild`, `lastChild`, `childNodes`) meet the wrapper elements;
  - a script that skips empty text nodes and elements it did not make sees a bolded element as empty, and may append its new text after the old (recognised for YouTube's `yt-formatted-string` only, §5).
- **Costly page styles:** where every style recalculation is expensive (a long Substack article; a page with many `:has()` rules), the frames after the first slices still take 50-70 ms, and a client-side navigation that replaces much of such a page takes more, smaller frames than one big one would (more style work in total, shorter frames). While on, a page has about three times as many elements, so interactions that restyle the whole page take about twice as long (opening the Share menu on a long Substack post: about 1 s → 2 s; collapsing a comment on a 765-comment Hacker News thread: 80 → 200 ms; the pre-review build measured the same).
- **Late React hydration:** an app whose `hydrateRoot` runs after Skimbold wrapped its server markup reports hydration errors (React #418, #423, #425), client-renders once, and then works.
- **Text a page keeps re-rendering** is bolded once it settles; **text runs in flex/grid containers** stay plain; **late-hydrating islands** may re-render once; **copied rich text** keeps structure, links and emphasis but not the page's fonts and colours.
- **Copy cases left to the browser and the page:** a selection that runs from the document into an open shadow root has no range within one tree (`getComposedRanges` crosses roots and `getRangeAt(0)` is collapsed), and `Selection.toString()` leaves out the other tree's text, so the browser's own copy runs, with our markup and its inlined bold; a page's own `copy` handler that clones the selection gets unstyled `skb-*` elements (the engine steps aside when the page has handled the event).
- **Custom elements defined late:** the look at hostless custom elements stops after five quiet looks, so one defined after about 10 s of an unchanging page is bolded when the page next changes.
- **Frames on ad-heavy pages:** each frame that loads later is asked for its state and, without an engine, gets one injected, even when it has no text (on a news site with about 300 ad frames: some 460 injections, and about 1 s more main-thread time on the top page, per 20 s).
